# tools/config_registries

The names each registry of the stack accepts, collected from the registries themselves into
`humanoid_nmpc/humanoid_mpc_config/config_registries.textproto` (a `humanoid_mpc_config.ConfigRegistries`). The tuning
GUI reads that file and offers a string field whose `(humanoid_mpc_config.tuning)` option names a registry
(`registry: "contact_estimator"`) as a drop-down of those names, so that no registry's names are written out in Python.

```bash
bazel run //tools/config_registries:print_config_registries   # write the file in the checkout
```

Run it after a registry gains, loses or renames a name. `//tools/config_registries:config_registries_test` fails until
the file is written again; it also requires that every registry offers names, once each, and that each name is one its
registry's own resolver accepts. `//humanoid_nmpc/remote_control:test_config_registries` requires that the file lists
exactly the registries the schemas name, and every name the shipped files give a registry string.

The file is committed rather than generated by the build: a genrule would rebuild the tool, which links the MPC, the
robot process and the simulator, in the exec configuration.

| Registry | Its names, from |
|---|---|
| `basis_generator_set`, `basis_regularization` | `basisGeneratorSetNames()`, `basisRegularizationNames()` (humanoid_common_mpc) |
| `centroidal_model`, `stance_constraint`, `foot_cost_phases` | `centroidalModelNames()`, `stanceConstraintNames()`, `footCostPhasesNames()` (humanoid_common_mpc/config) |
| `contact_estimator` | `robot::model::ContactEstimatorRegistry` and the simulator's `cheater_sim` |
| `contact_input_parameterization`, `contact_schedule_source` | `contactInputParameterizationNames()`, `contactScheduleSourceNames()` |
| `contact_planner`, `contact_planning_term` | `knownPlannerNames()`, `knownTermNames()` of every list |
| `contact_planner_threading`, `terminal_dcm_target` | `plannerThreadingNames()`, `terminalDcmTargetNames()` (humanoid_common_mpc/config) |
| `gantry_hold`, `projectile`, `visualization` | `gantryHoldNames()`, `availableProjectiles()`, `availableVisualizations()` (mujoco_sim_interface) |
| `hard_constraint`, `soft_constraint`, `mpc_cost` | `mpcHardConstraintNames()`, `mpcSoftConstraintNames()`, `mpcCostNames()` |
| `locomotion_heuristic` | `knownHeuristicNames()` of every list |
| `telemetry_sink`, `wb_mpc_feedforward` | `TelemetrySinkRegistry::names()`, `wbMpcFeedforwardNames()` (the robot process) |

A registry named in a schema for the first time is added to `collectConfigRegistries()` (`ConfigRegistries.cpp`,
LINT-tied to the `registry` option of `tuning_options.proto`) and to the resolvers of the test.
